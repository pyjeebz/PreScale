PreScale is an open-source CLI load tester built for developers doing pre-launch readiness checks. Point it at a URL — local or staging — and it ramps real traffic until something gives, then tells you in plain English what failed first, at what concurrency, and why. You don't write scripts, you don't sign up for anything, and you don't need to interpret a wall of histograms. You get an answer.

## Why PreScale?

Most load-testing tools are frameworks: you script a scenario, configure a runner, interpret the charts, and eventually form your own conclusion. PreScale skips all of that. It is designed around a single question — *"Will my app survive the spike that's coming?"* — and it answers it directly.

### Zero config

There is nothing to write before you run your first test. No test scripts, no YAML, no account. One command and a URL is all PreScale needs to get started.

```bash
prescale run http://localhost:8000
```

### Stack-agnostic

PreScale tests a URL, not a framework. It doesn't care whether your app is running on Vercel, Fly.io, Railway, Kubernetes, a raw VPS, a serverless function, or a Raspberry Pi in your closet. If it responds to HTTP, PreScale can test it.

### A plain-English answer, not a histogram

Rather than handing you a spreadsheet of percentiles and leaving the interpretation to you, PreScale produces a verdict:

```text
Scale readiness: ⚠️  Survives ~90 (75–110) concurrent users
Traffic          ≈ 590 req/s, roughly 5,900 real visitors
```

The `investigate` command goes further — it identifies the bottleneck class, names the culprit route, and suggests a concrete fix.

### Honest about uncertainty

Load test results are inherently noisy. PreScale represents that honestly: every verdict comes with a calibrated confidence band (e.g. `75–110 concurrent users`) and a stable/uncertain flag, so you know whether to trust the number or re-run with `--repeat`.

### Safe by default

Before hitting any non-local host, PreScale pauses and asks you to confirm you own it. The MCP server goes further — it refuses non-local hosts entirely unless you explicitly allowlist them. You won't accidentally hammer a third-party service or rack up a cloud bill without knowing.

### Every deploy, not just once

Capacity changes with every deploy. The [GitHub Action](/guides/github-action) load-tests each preview deploy and keeps one comment on the pull request: the capacity change against `main`, what breaks first, and the fix. A free dashboard at [prescale.dev/dashboard](https://prescale.dev/dashboard) keeps the history per site. Both are optional: the CLI works fully offline, and nothing leaves your machine unless you ask ([what gets uploaded](/reference/data-boundary)).

## PreScale vs other load testers

PreScale is not a replacement for full-featured load-testing frameworks — it occupies a different niche. If you need to simulate complex multi-step user journeys with custom logic, k6 or Locust are the right tools. If you need a fast, zero-ceremony answer to *"does my app survive the launch?"*, PreScale is built for exactly that.

| | **PreScale** | **Locust** | **k6** |
| - | - | - | - |
| Setup required | None — one install command | Write a Python locustfile | Write a JS test script |
| Output | Plain-English verdict + fix | Charts and statistics | Charts and statistics |
| Bottleneck diagnosis | ✅ Built in | ❌ Manual interpretation | ❌ Manual interpretation |
| Scripting | Not needed | Required | Required |
| Confidence band | ✅ Yes | ❌ No | ❌ No |
| Check on every PR | ✅ GitHub Action with one PR comment | ❌ Build it yourself | ❌ Build it yourself |
| Safe by default | ✅ Prompts before non-local | ❌ No prompt | ❌ No prompt |
| Runs on your machine | ✅ Yes | ✅ Yes | ✅ Yes |
| Best for | Pre-launch readiness, fast feedback loops | Complex scripted scenarios | Complex scripted scenarios |

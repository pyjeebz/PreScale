Every `prescale run` and `prescale investigate` saves a versioned JSON file to `.prescale/runs/<id>.json`. The `prescale run --json` flag emits the same shape to stdout, so the file you get on disk and the JSON you pipe to another tool are always identical. Use `prescale schema` to print the full machine-readable JSON Schema at any time.

***

## Top-level fields

The root object has the following properties. Fields marked **required** must be present on every result; the remaining fields are conditionally present based on which command was run and which options were used.

<ResponseField name="schema_version" type="integer" required>
  Always `1`. Additive fields may appear in future releases without bumping this version, so your consumer should ignore unknown properties.
</ResponseField>

<ResponseField name="kind" type="string" required>
  `"run"` for a standard `prescale run`, or `"audit"` for a `prescale audit` result.
</ResponseField>

<ResponseField name="id" type="string" required>
  The filename stem of the saved result (e.g. `20260628T173648Z`). IDs sort chronologically so `ls .prescale/runs/` gives you results in time order.
</ResponseField>

<ResponseField name="tool_version" type="string" required>
  The version of `prescale` that produced this result (e.g. `"1.0.0"`).
</ResponseField>

<ResponseField name="created_at" type="string" required>
  UTC ISO-8601 timestamp, e.g. `"2026-06-28T17:36:48Z"`.
</ResponseField>

<ResponseField name="warning" type="string | null">
  A human-readable warning emitted during the run (e.g. robots.txt signal, rate-cap hit), or `null` if everything was clean.
</ResponseField>

<ResponseField name="target" type="object" required>
  Describes what was load-tested.

  <Expandable title="target properties">
    <ResponseField name="target.url" type="string" required>
      The base URL passed to the command.
    </ResponseField>

    <ResponseField name="target.host" type="string" required>
      The resolved hostname (e.g. `"staging.myapp.com"`).
    </ResponseField>

    <ResponseField name="target.routes" type="string[]" required>
      The list of route paths that were tested (e.g. `["/", "/api/search"]`).
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="config" type="object" required>
  The exact configuration used for this run. See [config fields](#config-fields) below.
</ResponseField>

<ResponseField name="verdict" type="object" required>
  The top-level capacity verdict. See [verdict fields](#verdict-fields) below.
</ResponseField>

<ResponseField name="stages" type="Stage[]" required>
  Per-level load metrics. See [stages](#stages) below.
</ResponseField>

<ResponseField name="environment" type="object">
  Git context captured at run time. Present only when the run was executed inside a git repository.

  <Expandable title="environment properties">
    <ResponseField name="environment.git_commit" type="string | null">
      The current commit SHA, or `null` if unavailable.
    </ResponseField>

    <ResponseField name="environment.git_branch" type="string | null">
      The current branch name, or `null` if unavailable.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="investigation" type="object">
  Root-cause diagnosis. Present only when `prescale investigate` ran. See [investigation fields](#investigation-fields) below.
</ResponseField>

<ResponseField name="profile" type="object">
  Launch-scenario framing. Present only when `--profile` was used.

  <Expandable title="profile properties">
    <ResponseField name="profile.name" type="string">
      The scenario identifier (e.g. `"product-hunt"`).
    </ResponseField>

    <ResponseField name="profile.label" type="string">
      Human-readable scenario name (e.g. `"a Product Hunt #1 launch"`).
    </ResponseField>

    <ResponseField name="profile.peak_users" type="integer">
      The concurrent-user peak modelled for this scenario.
    </ResponseField>

    <ResponseField name="profile.would_survive" type="boolean">
      `true` if `survives_users` meets or exceeds `peak_users`.
    </ResponseField>
  </Expandable>
</ResponseField>

## config fields

The `config` object records every tunable that governed the run. You can reproduce a run exactly by replaying these values as CLI flags.

<ResponseField name="config.method" type="string" required>
  HTTP method used (e.g. `"GET"`).
</ResponseField>

<ResponseField name="config.max_users" type="integer" required>
  Peak virtual users the ramp targeted.
</ResponseField>

<ResponseField name="config.stage_seconds" type="number" required>
  Seconds held at each load level.
</ResponseField>

<ResponseField name="config.latency_wall_s" type="number" required>
  p95 latency threshold in seconds. A stage where p95 exceeds this is considered failed.
</ResponseField>

<ResponseField name="config.error_threshold" type="number" required>
  Error-rate threshold (0–1). A stage where the error rate exceeds this is considered failed.
</ResponseField>

<ResponseField name="config.max_rps" type="number | null" required>
  Aggregate requests-per-second ceiling, or `null` if no cap was applied.
</ResponseField>

<ResponseField name="config.warmup" type="boolean">
  Whether the warmup phase ran before measurement began.
</ResponseField>

<ResponseField name="config.repeat" type="integer">
  Number of full ramps pooled to tighten the confidence band.
</ResponseField>

<ResponseField name="config.think_time_s" type="number">
  Simulated pause (seconds) each virtual user waited between requests.
</ResponseField>

<ResponseField name="config.fail_under" type="integer | null">
  The `--fail-under` gate value, or `null` if no gate was set.
</ResponseField>

<ResponseField name="config.profile" type="string | null">
  The `--profile` scenario name, or `null` if no profile was used.
</ResponseField>

***

## verdict fields

The `verdict` object is the single most important part of the result — it summarises what PreScale found.

<ResponseField name="verdict.survives_users" type="integer" required>
  The highest concurrent-user level at which the app stayed within both the latency wall and error threshold. This is the headline capacity number.
</ResponseField>

<ResponseField name="verdict.max_tested" type="integer" required>
  The highest user level actually tested during the ramp.
</ResponseField>

<ResponseField name="verdict.onset_users" type="integer | null" required>
  The user level where failure first appeared, or `null` if the app survived all tested levels.
</ResponseField>

<ResponseField name="verdict.onset_reason" type="&#x22;errors&#x22; | &#x22;latency&#x22; | null" required>
  Whether the first failure was triggered by the error-rate threshold (`"errors"`) or the latency wall (`"latency"`), or `null` if there was no failure.
</ResponseField>

<ResponseField name="verdict.culprit_route" type="string | null" required>
  The route path that degraded first, or `null` if all routes degraded together or there was no failure.
</ResponseField>

<ResponseField name="verdict.bottleneck" type="string | null" required>
  A short plain-English description of the likely failure cause, or `null` if no failure was observed.
</ResponseField>

<ResponseField name="verdict.saturated" type="boolean" required>
  `true` if throughput plateaued while virtual users kept rising — a sign the server hit a concurrency ceiling.
</ResponseField>

<ResponseField name="verdict.saturation_users" type="integer | null" required>
  The user level where saturation was first detected, or `null` if saturation was not observed.
</ResponseField>

<ResponseField name="verdict.peak_rps" type="number" required>
  The highest requests-per-second observed across all stages.
</ResponseField>

<ResponseField name="verdict.marginal" type="boolean" required>
  `true` if the failure onset is close to `max_tested`, meaning the true ceiling may be higher than tested. Re-run with a larger `-u` value to be sure.
</ResponseField>

<ResponseField name="verdict.confidence" type="object">
  Statistical confidence band around the `survives_users` estimate.

  <Expandable title="confidence properties">
    <ResponseField name="verdict.confidence.survives_low" type="integer | null">
      Lower bound of the confidence interval.
    </ResponseField>

    <ResponseField name="verdict.confidence.survives_high" type="integer | null">
      Upper bound of the confidence interval.
    </ResponseField>

    <ResponseField name="verdict.confidence.stable" type="boolean">
      `true` when the band is tight enough to treat the verdict as reliable. `false` when results varied between repeat ramps — consider running with `--repeat 3` to tighten it.
    </ResponseField>
  </Expandable>
</ResponseField>

***

## stages

The `stages` array contains one object per tested load level, in ascending order of virtual users.

<ResponseField name="stages[].users" type="integer" required>
  Number of concurrent virtual users held at this stage.
</ResponseField>

<ResponseField name="stages[].rps" type="number" required>
  Aggregate requests per second observed during this stage.
</ResponseField>

<ResponseField name="stages[].p50_ms" type="integer" required>
  Median (p50) response latency in milliseconds across all routes.
</ResponseField>

<ResponseField name="stages[].p95_ms" type="integer" required>
  95th-percentile response latency in milliseconds across all routes.
</ResponseField>

<ResponseField name="stages[].p99_ms" type="integer" required>
  99th-percentile response latency in milliseconds across all routes.
</ResponseField>

<ResponseField name="stages[].error_rate" type="number" required>
  Fraction of requests that returned an error (0–1) at this stage.
</ResponseField>

<ResponseField name="stages[].errors" type="integer" required>
  Absolute error count at this stage.
</ResponseField>

<ResponseField name="stages[].total" type="integer" required>
  Total request count at this stage.
</ResponseField>

<ResponseField name="stages[].samples" type="integer">
  Number of latency samples recorded (may differ from `total` when sampling is applied at very high RPS).
</ResponseField>

<ResponseField name="stages[].routes" type="object" required>
  A map of route path → per-route stats. Each value has the same shape: `total`, `errors`, `error_rate`, `rps`, `p50_ms`, `p95_ms`, `p99_ms`.
</ResponseField>

***

## investigation fields

The `investigation` object is added to the result when you run `prescale investigate`. It contains the root-cause diagnosis for the culprit route.

<ResponseField name="investigation.culprit_route" type="string">
  The route path that was diagnosed (matches `verdict.culprit_route`).
</ResponseField>

<ResponseField name="investigation.bottleneck_class" type="string">
  Machine-readable bottleneck classification (e.g. `"connection_pool"`, `"concurrency_ceiling"`). See [Bottleneck Types](/reference/bottleneck-types) for the full list.
</ResponseField>

<ResponseField name="investigation.confidence" type="&#x22;high&#x22; | &#x22;medium&#x22; | &#x22;low&#x22;">
  How confident the classifier is in its diagnosis. `"high"` means the signal was unambiguous; `"low"` means you should re-run with `--repeat 3` for more data.
</ResponseField>

<ResponseField name="investigation.summary" type="string">
  Plain-English one-sentence diagnosis.
</ResponseField>

<ResponseField name="investigation.evidence" type="string[]">
  The specific signals that led to this classification — baseline vs loaded latency, static-route probe outcome, error kinds, server header, etc.
</ResponseField>

<ResponseField name="investigation.remediation" type="string[]">
  Ordered list of concrete fix recommendations, enriched with hints based on detected stack (e.g. gunicorn, nginx, pgbouncer).
</ResponseField>

<ResponseField name="investigation.stack" type="object">
  Key-value map of detected infrastructure signals — typically `server` (e.g. `"gunicorn/21.2.0"`) and `cdn` (e.g. `"Cloudflare"`). Empty if nothing was detected.
</ResponseField>

<Tip>
  Run `prescale schema` to print the full JSON Schema in your terminal — useful for validating results programmatically or generating TypeScript types. Add `.prescale/` to your `.gitignore` to keep run artifacts out of source control (except any baseline files you deliberately commit for CI comparison).
</Tip>
